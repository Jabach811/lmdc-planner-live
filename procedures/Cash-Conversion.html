Balance Import · Method 01 of 03

Cash
conversion.
The simplest path.

Prior recordkeeper liquidates the assets and wires cash. Funds land in the Advance Employer account first — not directly to participants — and are distributed only once the final files arrive and reconcile.

§ 02 · Three phases

Prep, wire day, post-wire.

Phase · Prep

Set the table

  • Build Source Mapping from prior-RK test files
  • Send to QA / TC / TM immediately on completion
  • Build Informatica parameter file for the Cash workflow
  • Confirm asset transfer date with the prior RK
Phase · Wire Day

Receive the wire

  • −3 days · advance heads-up to vendor & Cashiering
  • Day of · request wire breakdown ASAP from vendor
  • Book wire in system → notify Cashiering
  • Process all incoming assets → Advance Employer account
Phase · Post-Wire

Distribute, reconcile

  • Receive final files, confirm completeness
  • Liquidate Advance Employer account
  • Process proceeds → participant accounts
  • Verify balances · final reconciliation

§ 03b · Flow

Wire to participant, step by step.

Cash conversion is a quiet, linear path: wire arrives, sits, then distributes. The only branch is the gate that holds the holding account closed until the final file confirms.

Key rule All assets go to the Advance Employer account first — no direct participant routing on wire day. The participant-level distribution waits for the final file to confirm the breakdown.
Common mistake Building fund mapping for a cash conversion. It's wasted work — and it's a flag that the conversion type wasn't confirmed early. Cash needs source mapping only.
Workflow test flag The Cash workflow has a test mode. Verify the test flag in the parameter file matches the run intent — every single time. Test-on-live or live-on-test produces output that looks correct but isn't.
